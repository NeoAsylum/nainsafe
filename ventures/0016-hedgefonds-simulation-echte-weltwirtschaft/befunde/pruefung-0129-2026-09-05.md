# Pruefung 0129 -- der Bezeichnerriegel

Jede Zahl unten stammt aus eigenen Laeufen. Gebaut wurde ausschliesslich in
Wegwerf-Baubaeume unter `$TMPDIR`; der Repo-Baubaum und der Quellbaum blieben
unberuehrt (Arbeitskopie per `shutil.copytree`, `bau`- und `befunde`-Inhalte
ausgelassen, `befunde/pruefung-0066/nachbau.py` nachkopiert, weil die
Konfiguration sie verlangt). Den Nachweis des Bauagenten habe ich erst **nach**
den eigenen Messungen gegengelesen.

## Bedingung 1 -- gemessen, erfuellt

`cmake -S werkzeuge/bezeichner -B $TMPDIR/.../allein -DCMAKE_BUILD_TYPE=RelWithDebInfo`,
`--build`, `ctest`: 1 von 1 bestanden. Das Binary gegen den **echten** Baum
(lesend): Code 0. Der Bericht nennt die drei verlangten Zahlen -- 5.682
Kommentarzeilen, 898 gepruefte Bezeichner, 44 uebergangene Fundstellen -- und
druckt jede Fundstelle mit Name, Regel, Datei und Zeile, dazu die Summe je Regel.
Identisch mit dem Nachweis des Bauagenten bis auf die Datei- und Ordnernamen
(417 dort, 419 heute): eine Zahl mit Verfallsdatum, ohne Urteilswirkung.

## Bedingung 2, die tragende -- gemessen, erfuellt

Altbaum: In der Arbeitskopie `kern/include/kern/zustand.hpp` vollstaendig auf den
Stand `c30acc5^` gesetzt (der juengste Commit an dieser Datei traegt den
0101-Wortlauttausch `schreibe` -> `lege_ab`; davor nennt der Kommentar am
Fehlerwert der Adresssuche wieder `lies`, `schreibe`, `index_zu_adresse`).

1. **Mit** der Regel (geliefertes Programm): Code **1**, Meldung nennt
   `schreibe`, `kern/include/kern/zustand.hpp` (Zeile 677).
2. **Ohne** die Regel (Ein-Zeilen-Mutant `zugesichert = true` -> `= false` in
   `lies_datei`, mit Trefferbremse `count == 1`): Code **0**, kein Befund.
   Die erste Mutantenform `if (!zugesichert)` -> `if (true)` starb an
   `-Werror=unused-but-set-variable` -- an der Werkzeugkette, nicht am Test.

Beide Laeufe auf demselben Baum, Unterschied eine Zeile. Vorher und nach jeder
Ruecknahme M0 gefahren (Code 0), viermal.

## Bedingung 3 -- gemessen, erfuellt

Alle 44 uebergangenen Fundstellen tragen eine der vierzehn benannten Regeln
(13 Regeln kommen vor, `vergiftet` an diesem Stand nicht -- die Bedingung
verlangt das nicht). Im Quelltext gibt es keine Liste geduldeter Namen: Die
einzigen eingebauten Listen sind die C++20-Schluesselwoerter, die Wendungen der
Regel `abgelegter_name` und der handgefuellte Bestand des Selbsttests
(`pruefbestand()`), der nie gegen den Baum laeuft. Vergiftete Namen, Schluessel,
Bauziele, Dateinamen und Behaelter werden aus dem Baum gelesen.

## Bedingung 4 -- gemessen, erfuellt

Arbeitsbereichsbau gegen den echten Quellbaum, Baubaeume unter `$TMPDIR`:
Sanitizer **an** 16 von 16 bestanden, Sanitizer **aus** 16 von 16 bestanden.
Zaehlung beider Staende im selben Messaufbau (Arbeitskopie, Vorstand =
`CMakeLists.txt` vom Stand `497bcbc^`): 15 -> 16, Mengendifferenz exakt
`{bezeichner_riegel}`.

## Wird er rot, wenn man die Sache kaputtmacht? Ja, gemessen

* Erfundener toter Name **mit** Unterstrich (`lege_ab_alt`) in einen
  Kern-Kommentar der Kopie gesetzt: Code 1, Fundstelle korrekt.
* Einteiliger Name ohne jede Spur im Code (`xyzzy`): Code 0, gedruckt als
  `fremdwort` im Nachlass -- exakt der im Kopf der Quelle ausgeschriebene
  blinde Fleck, kein verdeckter.
* Alle vier `requires { &Z::...; }`-Zeilen der Zustandsprobe unkenntlich
  gemacht: Code **2** (gegenstandslos), nicht 0 -- die Vorsorge gegen den
  stillen Ausfall greift.

## Abgeschwaechte Tests: keine

Die 0129-Anteile der Commits (`497bcbc` traegt die zwei Quelldateien und die
Mitgliederliste, `2f8fe1c` den Nachweis; Runner-Buendelung unter fremdem
Betreff, bekanntes Muster) sind rein additiv: +46/+1553 neue Dateien, die
Vorhabens-`CMakeLists.txt` aendert nur Kommentar und Mitgliederliste. Kein
Test entfernt, keine Schwelle gesenkt, kein Eintrag uebersprungen. Die
Falltabellen des Selbsttests tragen von Hand begruendete Erwartungen, keine
aus dem Lauf uebernommenen.

## Randnotiz ohne Urteilswirkung

Der Ein-Zeilen-Mutant aus Bedingung 2 besteht den kompletten Selbsttest **und**
den `ctest` am heutigen Baum gruen: Der Selbsttest prueft `zusicherungen()` als
Funktion und die Regeln an einem handgefuellten Bestand, aber nicht die
Kopplung der beiden im Einlesepfad (`lies_datei`). Der Rotnachweis der Abnahme
war einmalig; eine kuenftige Regression genau an der tragenden Zeile bliebe
unbemerkt, bis wieder ein toter Name in Zusicherungsform auftaucht. Das ist
kein Mangel gegen die Abnahme -- sie verlangt die zwei gezeigten Laeufe, und
die sind erbracht -- aber eine offene Deckungsluecke. Vorschlag: Paket 0138.
